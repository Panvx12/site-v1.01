# 8. 錯誤處理

Rust 將錯誤分為兩類：

| 類型 | 機制 | 場景 |
|------|------|------|
| **不可恢復** | `panic!` | 程式 bug、不可能狀態 |
| **可恢復** | `Result<T, E>` | 檔案不存在、解析失敗 |

### 8.1 `panic!`

```rust
fn main() {
    let v = vec![1, 2, 3];
    // v[99];            // 越界 → panic
    // panic!("崩潰了");
}
```

### 8.2 `Result<T, E>`

```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

```rust
use std::fs::File;

fn main() {
    match File::open("hello.txt") {
        Ok(file) => println!("已開啟 {file:?}"),
        Err(e) => println!("開啟失敗：{e}"),
    }
}
```

### 8.3 `unwrap` 與 `expect`

```rust
let f = File::open("a.txt").unwrap();                  // Err 時 panic
let f = File::open("a.txt").expect("無法開啟 a.txt");   // 附帶訊息
```

> 建議：正式程式碼盡量避免 `unwrap`，原型或測試中可使用。

### 8.4 `?` 運算子：錯誤傳播

```rust
use std::fs;
use std::io;

fn read_username() -> Result<String, io::Error> {
    let s = fs::read_to_string("user.txt")?;  // 出錯則直接回傳 Err
    Ok(s.trim().to_string())
}
```

`?` 也可用於 `Option`：

```rust
fn first_char_upper(s: &str) -> Option<char> {
    let c = s.chars().next()?;
    Some(c.to_ascii_uppercase())
}
```

### 8.5 自訂錯誤型別

```rust
use std::fmt;

#[derive(Debug)]
enum AppError {
    Parse(std::num::ParseIntError),
    Negative(i64),
}

impl fmt::Display for AppError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            AppError::Parse(e) => write!(f, "解析失敗：{e}"),
            AppError::Negative(n) => write!(f, "不可為負數：{n}"),
        }
    }
}

impl std::error::Error for AppError {}

impl From<std::num::ParseIntError> for AppError {
    fn from(e: std::num::ParseIntError) -> Self {
        AppError::Parse(e)
    }
}

fn parse_positive(s: &str) -> Result<i64, AppError> {
    let n: i64 = s.parse()?;        // 自動透過 From 轉換
    if n < 0 {
        return Err(AppError::Negative(n));
    }
    Ok(n)
}
```

> 實務上常用第三方 crate：應用程式用 **`anyhow`**，函式庫用 **`thiserror`**。
