# 第 13 章　綜合練習與學習資源

## 13.1 綜合專題：同步 FIFO 的設計與驗證

### 規格

- 參數化：`DEPTH = 16`、`WIDTH = 8`
- 介面：`clk`、`rst_n`、`wr_en`、`wdata`、`rd_en`、`rdata`、`full`、`empty`
- 滿時寫入無效、空時讀取無效
- 讀資料於讀取請求後下一個週期有效

### Step 1：設計（第 2–5 章）

```systemverilog
module sync_fifo #(
  parameter int DEPTH = 16,
  parameter int WIDTH = 8
)(
  input  logic             clk, rst_n,
  input  logic             wr_en, rd_en,
  input  logic [WIDTH-1:0] wdata,
  output logic [WIDTH-1:0] rdata,
  output logic             full, empty
);
  localparam int AW = $clog2(DEPTH);

  logic [WIDTH-1:0] mem [DEPTH];
  logic [AW:0]      wptr, rptr;     // 多 1 位元用來區分滿與空

  assign empty = (wptr == rptr);
  assign full  = (wptr[AW-1:0] == rptr[AW-1:0]) && (wptr[AW] != rptr[AW]);

  always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
      wptr <= '0; rptr <= '0; rdata <= '0;
    end else begin
      if (wr_en && !full) begin
        mem[wptr[AW-1:0]] <= wdata;
        wptr <= wptr + 1'b1;
      end
      if (rd_en && !empty) begin
        rdata <= mem[rptr[AW-1:0]];
        rptr  <= rptr + 1'b1;
      end
    end
  end
endmodule
```

### Step 2：介面與基本 testbench（第 6–7 章）

- 建立 `fifo_if`，含 clocking block 與 modport
- 寫 directed test：寫滿 → 讀空 → 邊寫邊讀

### Step 3：斷言（第 10 章）

```systemverilog
// 滿時不可寫入造成指標變動；空時不可讀
a_no_overflow:  assert property (@(posedge clk) disable iff (!rst_n)
                  full  && wr_en |=> $stable(wptr));
a_no_underflow: assert property (@(posedge clk) disable iff (!rst_n)
                  empty && rd_en |=> $stable(rptr));
a_not_both:     assert property (@(posedge clk) disable iff (!rst_n)
                  !(full && empty));
```

### Step 4：OOP 與隨機化（第 8–9 章、12 章）

- `Transaction`：`rand` 的 `op`（寫/讀/同時）、`data`、`gap`（間隔週期）
- 約束：寫入機率高於讀取，製造「滿」的情境；再反轉製造「空」的情境
- Scoreboard：用 SV `queue` 作為參考模型，比對讀出資料

### Step 5：覆蓋率（第 11 章）

- 覆蓋 `full`、`empty` 是否都曾出現
- 覆蓋「滿時仍寫入」、「空時仍讀取」
- Cross：`wr_en × rd_en × {full, empty, normal}`

## 13.3 練習題與提示

**Q1.** 以下程式有何問題？

```systemverilog
always_ff @(posedge clk)
  a = b;
```

> **提示**：`always_ff` 內應使用非阻塞賦值 `<=`，否則可能產生模擬競爭。

**Q2.** 為什麼下列會產生 latch？如何修正？

```systemverilog
always_comb
  if (sel) y = a;
```

> **提示**：`sel == 0` 時 `y` 未賦值。加入 `else` 或預設值。

**Q3.** `a |-> b` 與 `a |=> b` 的差別？

> **提示**：前者在同一週期檢查 b，後者在下一週期。

**Q4.** 下列程式印出什麼？

```systemverilog
class C; int x = 1; endclass
C a = new();
C b = a;
b.x = 5;
$display(a.x);
```

> **提示**：`5`。`b = a` 只複製句柄。

**Q5.** `randc` 與 `rand` 的差別？

> **提示**：`randc` 會循環用盡所有可能值才重複，`rand` 每次獨立隨機。

## 13.4 常見錯誤清單

1. 在 `always_ff` 用 `=`、在 `always_comb` 用 `<=`
2. 組合邏輯忘了預設值 → latch
3. 同一變數被多個 `always` 驅動
4. 使用 class 句柄前未 `new()`
5. 忘記檢查 `randomize()` 回傳值
6. 斷言缺少 `disable iff`，重置期間誤報
7. testbench 沒有 timeout，模擬卡死
8. 比較含 X/Z 的值時用 `==` 而非 `===`/`!==`
