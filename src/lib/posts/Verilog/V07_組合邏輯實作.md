## 7.1 3-to-8 解碼器

### 規格

- 輸入：3 位元 `in`、致能 `en`
- 輸出：8 位元 `out`
- `en = 1` 時，第 `in` 位元為 1，其他為 0（像「一次只亮一盞燈」）；`en = 0` 時全 0

| in | out（en=1） |
|:--:|:-----------:|
| 000 | 00000001 |
| 001 | 00000010 |
| 010 | 00000100 |
| 011 | 00001000 |
| 100 | 00010000 |
| 101 | 00100000 |
| 110 | 01000000 |
| 111 | 10000000 |

### 設計

```verilog
module dec3to8 (
  input  wire [2:0] in,
  input  wire       en,
  output reg  [7:0] out
);
  always @(*) begin
    out = 8'b0000_0000;               // 預設值
    if (en)
      out[in] = 1'b1;                 // 把第 in 位元設成 1
  end
endmodule
```

`out[in]`：用變數當位元編號，意思是「第 `in` 位元」。

### 測試

```verilog
`timescale 1ns/1ps
module tb_dec3to8;
  reg  [2:0] in;
  reg        en;
  wire [7:0] out;
  integer i;

  dec3to8 dut (.in(in), .en(en), .out(out));

  initial begin
    en = 1;
    for (i = 0; i < 8; i = i + 1) begin
      in = i[2:0];
      #10;
      $display("in=%b out=%b", in, out);
    end
    en = 0; in = 3'b101; #10;
    $display("en=0 in=%b out=%b", in, out);
    $finish;
  end
endmodule
```

### 預期輸出

```
in=000 out=00000001
in=001 out=00000010
in=010 out=00000100
in=011 out=00001000
in=100 out=00010000
in=101 out=00100000
in=110 out=01000000
in=111 out=10000000
en=0 in=101 out=00000000
```

## 7.2 優先權編碼器

### 規格

4 個請求線 `req[3:0]`，輸出「**最高位且為 1 的編號**」，並告訴我有沒有任何請求 (`valid`)。

| req | idx | valid |
|:---:|:---:|:-----:|
| 1??? | 3 | 1 |
| 01?? | 2 | 1 |
| 001? | 1 | 1 |
| 0001 | 0 | 1 |
| 0000 | 0 | 0 |

（`?` 表示不在乎）

### 設計

```verilog
module prio_enc (
  input  wire [3:0] req,
  output reg  [1:0] idx,
  output reg        valid
);
  always @(*) begin
    valid = 1'b1;
    casez (req)
      4'b1???: idx = 2'd3;
      4'b01??: idx = 2'd2;
      4'b001?: idx = 2'd1;
      4'b0001: idx = 2'd0;
      default: begin
        idx   = 2'd0;
        valid = 1'b0;
      end
    endcase
  end
endmodule
```

### 測試重點

req = `0101` 時，最高的 1 在第 2 位 → `idx = 2`、`valid = 1`；req = `0000` 時 → `valid = 0`。

```verilog
`timescale 1ns/1ps
module tb_prio;
  reg  [3:0] req;
  wire [1:0] idx;
  wire       valid;
  integer i;

  prio_enc dut (.req(req), .idx(idx), .valid(valid));

  initial begin
    for (i = 0; i < 16; i = i + 1) begin
      req = i[3:0];
      #10;
      $display("req=%b idx=%0d valid=%b", req, idx, valid);
    end
    $finish;
  end
endmodule
```

預期輸出的前幾行與最後幾行：

```
req=0000 idx=0 valid=0
req=0001 idx=0 valid=1
req=0010 idx=1 valid=1
req=0011 idx=1 valid=1
req=0100 idx=2 valid=1
...
req=1110 idx=3 valid=1
req=1111 idx=3 valid=1
```

## 7.3 4 位元加法器（含進位）

### 規格

`a + b + cin` = `{cout, sum}`。`a`、`b`、`sum` 各 4 位元。

### 設計

```verilog
module add4 (
  input  wire [3:0] a, b,
  input  wire       cin,
  output wire [3:0] sum,
  output wire       cout
);
  assign {cout, sum} = a + b + cin;
endmodule
```

一行就完成：左邊 5 位元（`cout` 是最高位）接收結果。

### 自我檢查 testbench

手動看 256 種組合不可能，所以讓 testbench **自己比對**：

```verilog
`timescale 1ns/1ps
module tb_add4;
  reg  [3:0] a, b;
  reg        cin;
  wire [3:0] sum;
  wire       cout;
  integer i, j, errors;

  add4 dut (.a(a), .b(b), .cin(cin), .sum(sum), .cout(cout));

  initial begin
    errors = 0;
    cin = 1'b0;
    for (i = 0; i < 16; i = i + 1) begin
      for (j = 0; j < 16; j = j + 1) begin
        a = i[3:0];
        b = j[3:0];
        #1;
        if ({cout, sum} !== i + j) begin
          errors = errors + 1;
          $display("ERROR: %0d + %0d = %0d (got %0d)", i, j, i + j, {cout, sum});
        end
      end
    end

    if (errors == 0) $display("PASSED: all 256 cases correct");
    else             $display("FAILED: %0d errors", errors);
    $finish;
  end
endmodule
```

**新語法**：

- 兩層 `for`：窮舉所有 `a`、`b` 組合
- `{cout, sum} !== i + j`：用 **`!==`** 比較（連 x/z 也會抓到），`i + j` 是正確答案
- `errors` 計算出錯次數，最後印 **PASSED / FAILED**

### 預期輸出

```
PASSED: all 256 cases correct
```

💡 這是專業做法：**不要靠眼睛看，讓 testbench 自己判斷對錯。**

## 7.4 比較器

### 規格

兩個 4 位元數 `a`、`b`，輸出 `lt`（小於）、`eq`（等於）、`gt`（大於），三個**只有一個為 1**。

```verilog
module cmp4 (
  input  wire [3:0] a, b,
  output wire       lt, eq, gt
);
  assign lt = (a <  b);
  assign eq = (a == b);
  assign gt = (a >  b);
endmodule
```

### 練習式測試

用兩層 `for` 窮舉，判斷 `lt + eq + gt` 一定等於 1，並且和 `a`、`b` 的大小關係一致（練習 2）。

## 7.5 簡易 ALU（算術邏輯單元）

### 規格

| op | 運算 |
|:--:|------|
| 0 | a + b |
| 1 | a − b |
| 2 | a & b |
| 3 | a \| b |
| 4 | a ^ b |
| 5 | `a << 1` |
| 6 | a >> 1 |
| 其他 | 0 |

輸出 `y`（8 位元）與 `zero`（`y` 為 0 時為 1）。

### 設計

```verilog
module alu (
  input  wire [7:0] a, b,
  input  wire [2:0] op,
  output reg  [7:0] y,
  output reg        zero
);
  always @(*) begin
    case (op)
      3'd0:    y = a + b;
      3'd1:    y = a - b;
      3'd2:    y = a & b;
      3'd3:    y = a | b;
      3'd4:    y = a ^ b;
      3'd5:    y = a << 1;
      3'd6:    y = a >> 1;
      default: y = 8'h00;
    endcase
    zero = (y == 8'h00);
  end
endmodule
```

注意：

- `case` 有 `default` → 不會產生 latch
- `zero` 在 `case` 之後算，依據算好的 `y`（阻塞賦值依序執行）

### 簡單測試

```verilog
`timescale 1ns/1ps
module tb_alu_simple;
  reg  [7:0] a, b;
  reg  [2:0] op;
  wire [7:0] y;
  wire       zero;

  alu dut (.a(a), .b(b), .op(op), .y(y), .zero(zero));

  initial begin
    a = 8'd12; b = 8'd5;
    op = 3'd0; #10; $display("add: y=%0d zero=%b", y, zero);
    op = 3'd1; #10; $display("sub: y=%0d zero=%b", y, zero);
    op = 3'd2; #10; $display("and: y=%b zero=%b", y, zero);
    op = 3'd5; #10; $display("shl: y=%0d zero=%b", y, zero);
    a = 8'd5; b = 8'd5;
    op = 3'd1; #10; $display("sub: y=%0d zero=%b", y, zero);
    $finish;
  end
endmodule
```

### 預期輸出

```
add: y=17 zero=0
sub: y=7 zero=0
and: y=00000100 zero=0
shl: y=24 zero=0
sub: y=0 zero=1
```

驗算：12+5=17；12−5=7；`1100 & 0101` = `0100`；12<<1=24；5−5=0 → zero=1 ✓。

## 7.6 七段顯示器解碼

### 什麼是七段顯示器？

數字顯示用的燈管，7 個小燈 a~g，點亮不同的燈組成數字：

```
  ─ a ─
 │     │
 f     b
 │     │
  ─ g ─
 │     │
 e     c
 │     │
  ─ d ─
```

### 規格

輸入 4 位元 BCD（0~9），輸出 7 位元 `seg = {g,f,e,d,c,b,a}`（共陰極，1 = 亮）。

| 數字 | seg (gfedcba) | 點亮 |
|:---:|:-------------:|------|
| 0 | 0111111 | a b c d e f |
| 1 | 0000110 | b c |
| 2 | 1011011 | a b d e g |
| 3 | 1001111 | a b c d g |
| 4 | 1100110 | b c f g |
| 5 | 1101101 | a c d f g |
| 6 | 1111101 | a c d e f g |
| 7 | 0000111 | a b c |
| 8 | 1111111 | 全亮 |
| 9 | 1101111 | a b c d f g |

### 設計

```verilog
module bcd7seg (
  input  wire [3:0] bcd,
  output reg  [6:0] seg
);
  always @(*) begin
    case (bcd)
      4'd0:    seg = 7'b0111111;
      4'd1:    seg = 7'b0000110;
      4'd2:    seg = 7'b1011011;
      4'd3:    seg = 7'b1001111;
      4'd4:    seg = 7'b1100110;
      4'd5:    seg = 7'b1101101;
      4'd6:    seg = 7'b1111101;
      4'd7:    seg = 7'b0000111;
      4'd8:    seg = 7'b1111111;
      4'd9:    seg = 7'b1101111;
      default: seg = 7'b0000000;     // 非 BCD：全滅
    endcase
  end
endmodule
```

💡 這是「**查表**」型設計：每個輸入對應一個固定輸出。真實的開發板可能是**共陽極**（0 = 亮），那就在輸出時整個反相：`assign seg_out = ~seg;`。

## 7.7 常見錯誤

| 錯誤 | 說明 | 解法 |
|------|------|------|
| 加法結果少一位 | 沒留進位位元 | 用 `{cout, sum}` |
| `casez` 的順序錯 | 優先權反了 | 高優先權的放上面 |
| 比較用 `=` | 變成賦值 | 用 `==` |
| 迴圈變數用 `reg` | 型別不適合 | testbench 用 `integer` |
| 只測少數幾筆就放心 | 漏掉邊界情況 | 窮舉，或測試 0、最大值、相鄰值 |

## 本章小結

- 做設計的順序：**規格 → 設計 → 驗證**
- 查表用 `case`，優先權用 `casez`，簡單運算用 `assign`
- testbench 要**自己判斷對錯**，印 PASSED / FAILED
- 輸入空間小（如 8 位元）時，直接**窮舉**最保險

## 小測驗

**Q1.** 如果優先權編碼器改寫成下面這樣（四個條件都是「只看一個位元」），輸入 `req = 4'b1111` 時 `idx` 會是多少？跟 `req[3]` 優先的設計有什麼差別？

```verilog
casez (req)
  4'b???1: idx = 2'd0;
  4'b??1?: idx = 2'd1;
  4'b?1??: idx = 2'd2;
  4'b1???: idx = 2'd3;
  default: idx = 2'd0;
endcase
```

<details><summary>看答案</summary>

`req = 4'b1111` 先符合最上面的 `4'b???1`，所以 `idx = 0`。這個寫法變成「**最低位元優先**」，和原本「最高位元優先」（`idx = 3`）剛好相反。重點：**`case` 由上往下比對，先符合的先用，所以優先權高的條件要放上面。**
</details>

**Q2.** 為什麼自我檢查要用 `!==` 而不是 `!=`？

<details><summary>看答案</summary>

`!=` 遇到 `x` 或 `z` 時結果是 `x`（`if` 會當成假），錯誤會被漏掉；`!==` 會把 `x`/`z` 也當成不同的值，能抓到這種問題。
</details>

**Q3.** ALU 中 `zero = (y == 8'h00);` 為什麼要放在 `case` **之後**？

<details><summary>看答案</summary>

因為 `zero` 要用到算好的 `y`。`always` 裡用阻塞賦值 `=` 是依序執行，所以要先算出 `y`，再算 `zero`。
</details>
