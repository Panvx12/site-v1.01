## 13.1 什麼叫「可合成」？

**合成 (synthesis)**：把你寫的 Verilog 轉成真正的邏輯閘與正反器（放進 FPGA 或做成晶片）。

> Verilog 是為了「模擬」而生的語言，語法很廣，但**只有一部分能被合成成電路**。

💡 比喻：Verilog 像一本包含「建築藍圖」與「施工現場筆記」的書；合成工具只看得懂藍圖的部分。

### 可合成的（寫在設計 RTL 裡）

| 類別 | 可以用 |
|------|--------|
| 資料型別 | `wire`、`reg`、向量、陣列（記憶體） |
| 描述 | `assign`、`always @(*)`、`always @(posedge clk ...)` |
| 控制 | `if`、`case`、`casez`、**邊界固定**的 `for`、`generate` |
| 運算 | 算術、位元、邏輯、移位、連接、`? :` |
| 其他 | `parameter`、`localparam`、`function`、子模組 |

### 不可合成的（只用在 testbench）

| 項目 | 原因 |
|------|------|
| `#10` 延遲 | 真實電路沒有「等 10 ns」這種指令 |
| `$display`、`$finish` 等 `$` 系統工作 | 只是模擬器的功能 |
| `initial`（用在 testbench） | 見下方說明 |
| `===`、`!==` | 硬體沒有 x / z 的比較 |
| 階層參考 `dut.u_cnt.cnt` | 不是真實連線 |
| `real` 浮點數 | 不能做成硬體 |
| `wait`、`fork/join`、`event` | 屬於模擬流程控制 |
| 邊界不固定的迴圈（`while (x)`） | 無法決定要做出幾份電路 |

> 關於 `initial`：在 FPGA 上，`initial` 常被用來設定暫存器開機初始值，很多工具支援；但在晶片 (ASIC) 不行，所以建議 RTL 一律靠**重置**來初始化，把 `initial` 留給 testbench。

### 一條簡單的規則

> **設計檔（RTL）裡，只用「可合成」的寫法；其他全部放在 testbench。**

## 13.2 常見的「意外硬體」

### 1. Latch（意外的記憶元件）

第 6 章：`always @(*)` 沒有涵蓋所有情況。

```verilog
// ❌ 產生 latch
always @(*) begin
  if (en) y = a;
end
```

### 2. 多重驅動

```verilog
// ❌ 兩個 always 同時驅動 q
always @(posedge clk) q <= a;
always @(posedge clk) q <= b;
```

兩個地方同時管同一條線，電路上會短路般衝突，模擬時出現 `x`。**一個訊號只能有一個驅動者。**

### 3. 敏感列表不完整

```verilog
// ❌ 少寫 c：模擬時 c 變化不會更新 y，合成後卻會
always @(a or b) y = a & b & c;

// ✅
always @(*) y = a & b & c;
```

### 4. 組合迴圈

```verilog
// ❌ y 依賴自己
assign y = a & y;
```

### 5. 位元寬度不一致

```verilog
wire [3:0] x = 8'hFF;      // 高位被截掉，只剩 4'hF
```

這些問題的共同點：**模擬可能看起來正常，但做成電路後行為不同**。所以要靠工具檢查。

## 13.3 用 lint 檢查：Verilator

**Lint** 是「語法與風格的靜態檢查」，不用模擬就能找出可疑的寫法。

```bash
verilator --lint-only -Wall mydesign.v
```

### 🧪 實驗

寫一個故意有 latch 的檔案 `bad.v`：

```verilog
module bad (
  input  wire a,
  input  wire en,
  output reg  y
);
  always @(*) begin
    if (en) y = a;
  end
endmodule
```

執行：

```bash
verilator --lint-only -Wall bad.v
```

你會看到包含 **`LATCH`** 字樣的警告，指出 `y` 在某些情況下沒有被賦值（確切文字依 Verilator 版本而異）。

### 常見的 lint 警告名稱

| 警告 | 意思 |
|------|------|
| `LATCH` | 推導出 latch |
| `WIDTH`（新版細分為 `WIDTHEXPAND`、`WIDTHTRUNC`） | 位元寬度不一致 |
| `UNUSED` | 宣告了卻沒用到的訊號 |
| `UNDRIVEN` | 沒有被驅動的訊號 |
| `MULTIDRIVEN` | 被多個地方驅動 |
| `BLKSEQ` | 時序區塊中用了 `=` |
| `CASEINCOMPLETE` | `case` 沒涵蓋所有情況 |

> **習慣：每寫完一個模組，先跑一次 lint，警告歸零再往下做。**

## 13.4 用 Yosys 合成並看結果

Yosys 是開源的合成工具。可以「實際把設計合成一次」，看會產生什麼。

```bash
yosys -p "read_verilog counter4.v; synth -top counter4; stat"
```

輸出的 `stat` 會統計使用了多少個正反器、邏輯閘。

### 用法 1：確認有沒有 latch

合成 `bad.v`：

```bash
yosys -p "read_verilog bad.v; synth -top bad; stat"
```

統計結果中會出現 **latch 類型的單元**（名稱含 `DLATCH`）。合成 `counter4.v` 則應該看到**正反器**（名稱含 `DFF`）而沒有 latch。

### 用法 2：比較不同寫法的大小

改變參數（例如位元寬度），重新 `stat`，觀察資源量如何成長。

### 用法 3：畫電路圖（需安裝 Graphviz）

```bash
yosys -p "read_verilog counter4.v; proc; opt; show -format svg -prefix counter4"
```

可以親眼看到你寫的 Verilog 變成怎樣的電路圖。這對理解「**程式碼 → 硬體**」非常有幫助。

> 輸出格式與單元名稱會因 Yosys 版本不同，請以你本機的實際輸出為準。

## 13.5 時序的基本概念

### 為什麼電路有速度上限？

訊號從一個正反器出發，經過一串邏輯閘，要在**下一個時脈邊緣到達之前**抵達下一個正反器。邏輯閘越多，花越久。

```
  ┌────┐        ┌──────────────┐        ┌────┐
  │ FF ├───────►│  組合邏輯    ├───────►│ FF │
  └─▲──┘        └──────────────┘        └─▲──┘
    │ clk               延遲                │ clk
```

### 重要名詞

| 名詞 | 白話 |
|------|------|
| **Setup time** | 時脈邊緣**之前**，資料必須已經穩定多久 |
| **Hold time** | 時脈邊緣**之後**，資料還必須維持多久 |
| **Clock-to-Q** | 正反器收到邊緣後，輸出出來要多久 |
| **關鍵路徑 (critical path)** | 延遲最長的那條路徑，**決定最高時脈** |

比喻：**接力賽**。每棒要在下一個哨聲前把棒子交給下一位。跑最慢的那一棒，決定整隊的節奏。

### 最高時脈頻率的算法

```
時脈週期 ≥ Clock-to-Q + 最長組合邏輯延遲 + Setup time
```

例：Clock-to-Q = 1 ns、組合邏輯 = 7 ns、Setup = 1 ns → 週期至少 9 ns → 最高約 1 ÷ 9 ns ≈ **111 MHz**。

### 違反 setup / hold 會怎樣？

正反器可能進入**亞穩態 (metastability)**：輸出在 0 和 1 之間「卡住」一小段時間，之後隨機變成 0 或 1，電路行為不可預測。

## 13.6 管線化 (Pipelining)

### 問題

組合邏輯太長（例如先乘兩次再相加）→ 關鍵路徑太長 → 時脈跑不快。

### 解法：切成多級，中間放暫存器

```
未管線：  a,b,c,d ──► [ 乘 + 乘 + 加 ] ──► y                      一個週期要做完
管線：    a,b,c,d ──► [ 乘 ] ─FF─► [ 加 ] ─FF─► y                  每級很短，時脈可更快
```

代價：結果晚出來（**延遲 latency** 增加），但每個時脈仍能吃新資料（**吞吐量 throughput** 不降反升）。

### 範例：兩級管線

```verilog
module mac_pipe (
  input  wire        clk,
  input  wire        rst_n,
  input  wire [7:0]  a, b, c, d,
  output reg  [16:0] y             // a*b + c*d 最大 130050 < 2^17
);
  reg [15:0] p1, p2;

  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
      p1 <= 16'd0;
      p2 <= 16'd0;
      y  <= 17'd0;
    end else begin
      p1 <= a * b;                 // 第 1 級：乘法
      p2 <= c * d;
      y  <= p1 + p2;               // 第 2 級：加法（用上一拍的 p1、p2）
    end
  end
endmodule
```

### Testbench

```verilog
`timescale 1ns/1ps
module tb_pipe;
  reg         clk = 1'b0;
  reg         rst_n;
  reg  [7:0]  a, b, c, d;
  wire [16:0] y;

  mac_pipe dut (.clk(clk), .rst_n(rst_n), .a(a), .b(b), .c(c), .d(d), .y(y));

  always #5 clk = ~clk;

  always @(negedge clk)
    if (rst_n) $display("t=%0d y=%0d", $time, y);

  initial begin
    rst_n = 1'b0;
    a = 0; b = 0; c = 0; d = 0;
    #22 rst_n = 1'b1;
    @(negedge clk);                          // t=30
    a = 8'd2; b = 8'd3; c = 8'd4; d = 8'd5;  // 2*3 + 4*5 = 26
    repeat (3) @(negedge clk);               // 到 t=60
    #1 $finish;
  end
endmodule
```

### 預期輸出

```
t=30 y=0
t=40 y=0
t=50 y=26
t=60 y=26
```

在 t=30 送入資料，**要等兩個時脈**（t=50）才看到結果 26 → 延遲 2 個時脈。這就是管線的 latency。

## 13.7 重置的同步釋放

非同步重置「放開」的瞬間若剛好碰上時脈邊緣，可能違反時序條件。常見解法：**非同步置位、同步釋放**。

```verilog
module reset_sync (
  input  wire clk,
  input  wire arst_n,       // 外部來的非同步重置
  output wire rst_n         // 提供給內部電路的重置
);
  reg r1, r2;

  always @(posedge clk or negedge arst_n) begin
    if (!arst_n) begin
      r1 <= 1'b0;
      r2 <= 1'b0;
    end else begin
      r1 <= 1'b1;
      r2 <= r1;
    end
  end

  assign rst_n = r2;
endmodule
```

- 重置進來（`arst_n=0`）時：**立刻**把 `rst_n` 拉成 0（非同步）
- 重置放開時：要經過**兩個時脈**才釋放 `rst_n`（同步）

### 驗證

```verilog
`timescale 1ns/1ps
module tb_rst;
  reg  clk = 1'b0;
  reg  arst_n;
  wire rst_n;

  reset_sync dut (.clk(clk), .arst_n(arst_n), .rst_n(rst_n));

  always #5 clk = ~clk;

  always @(negedge clk)
    $display("t=%0d arst_n=%b rst_n=%b", $time, arst_n, rst_n);

  initial begin
    arst_n = 1'b0;
    #22 arst_n = 1'b1;           // 在非時脈邊緣放開
    #30 $finish;                 // t=52
  end
endmodule
```

預期輸出：

```
t=10 arst_n=0 rst_n=0
t=20 arst_n=0 rst_n=0
t=30 arst_n=1 rst_n=0
t=40 arst_n=1 rst_n=1
t=50 arst_n=1 rst_n=1
```

`arst_n` 在 t=22 放開，但 `rst_n` 到 t=35（第二個上升緣）才跟著放開，所以 t=40 才看到 1。

## 13.8 跨時脈域 (CDC)

當一個訊號從「時脈 A 的電路」送到「時脈 B 的電路」，因為兩個時脈沒有固定的相位關係，一定有機會違反 setup/hold。

### 單一位元：兩級正反器同步器

```verilog
module sync2 (
  input  wire clk,
  input  wire rst_n,
  input  wire async_in,
  output wire sync_out
);
  reg m, s;
  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin m <= 1'b0; s <= 1'b0; end
    else        begin m <= async_in; s <= m; end
  end
  assign sync_out = s;
endmodule
```

第一級 `m` 可能進入亞穩態，但給它**一個完整的時脈週期**恢復，第二級 `s` 看到的就已經穩定了。（例：外部按鍵、感測器進來的訊號都要先過同步器。）

### ⚠️ 多位元訊號不能逐位元各自同步

8 位元匯流排的每個位元各接一個同步器，各位元可能差一個時脈才到，接收端會**暫時看到不存在的組合值**（例如 `0111 → 1000` 的變化途中短暫看到 `1111`）。

正確方式：

| 情況 | 做法 |
|------|------|
| 多位元資料 | 握手協定（資料穩定後才送「有效」旗標，且只同步旗標） |
| 計數器/指標 | 轉成**格雷碼**（相鄰值只差 1 位元）再同步 |
| 大量資料流 | 非同步 FIFO |

這屬於進階主題，現在只要記住：**跨時脈域不能直接接線**。

## 13.9 編碼風格準則

1. 一個檔案一個模組，檔名 = 模組名
2. 重置訊號命名：低態有效用 `rst_n`
3. 組合邏輯：`always @(*)` + `=`，開頭給預設值
4. 時序邏輯：`always @(posedge clk or negedge rst_n)` + `<=`
5. 所有 `case` 都有 `default`
6. 一個訊號只能被一個地方驅動
7. 位元寬度明確寫出（`4'd1`，不要裸寫 `1`）
8. 使用具名連接（`.a(x)`）
9. 常數用 `parameter` / `localparam`，不要寫「魔術數字」
10. RTL 裡不放 `#` 延遲與 `$display`
11. 不要自己用邏輯做時脈，用使能脈衝
12. 狀態機用三段式

## 13.10 Makefile：一個指令跑完整流程

> ⚠️ Makefile 的指令行開頭必須是 **Tab** 字元，不能用空白，否則會出現 `missing separator` 錯誤。

```make
RTL  = rtl/counter4.v
TB   = tb/tb_counter4.v
TOP  = counter4
SIM  = sim/sim.vvp

sim: $(RTL) $(TB)
	mkdir -p sim
	iverilog -g2005 -Wall -o $(SIM) $(RTL) $(TB)
	vvp $(SIM)

wave: sim
	gtkwave wave.vcd &

lint:
	verilator --lint-only -Wall $(RTL)

synth:
	yosys -p "read_verilog $(RTL); synth -top $(TOP); stat"

clean:
	rm -rf sim *.vcd

.PHONY: sim wave lint synth clean
```

使用：

```bash
make sim      # 編譯並模擬
make lint     # 檢查
make synth    # 合成看資源
make clean    # 清理
```

> 若在 testbench 的 `$dumpfile` 設定的是 `wave.vcd`，波形檔會出現在執行 `make` 的目錄。

## 本章小結

- 設計檔只寫**可合成**語法；模擬專用的東西放 testbench
- 常見意外硬體：**latch、多重驅動、敏感列表不完整、組合迴圈、位寬不一致**
- 用 **lint**（Verilator）和 **Yosys** 在模擬以外再檢查一次
- 時序：setup/hold、關鍵路徑決定最高時脈；**管線化**以延遲換速度
- 重置要同步釋放、跨時脈域不能直接接線、多位元不能逐位元同步

## 小測驗

**Q1.** 下面哪些**不能**寫在要合成的設計裡？`assign`、`#5`、`$display`、`case`、`always @(posedge clk)`

<details><summary>看答案</summary>

`#5` 和 `$display` 不能合成；`assign`、`case`、`always @(posedge clk)` 都可以。
</details>

**Q2.** 一條路徑：Clock-to-Q = 0.8 ns、組合邏輯 = 4.2 ns、Setup = 1 ns，最小時脈週期與最高頻率？

<details><summary>看答案</summary>

週期 ≥ 0.8 + 4.2 + 1 = **6 ns**，最高頻率約 1 ÷ 6 ns ≈ **166.7 MHz**。
</details>

**Q3.** 兩級管線的設計，輸入資料送進去之後，要等幾個時脈才看到結果？

<details><summary>看答案</summary>

**2 個時脈**（每一級暫存器各延遲一個時脈）。
</details>

**Q4.** 為什麼 8 位元的匯流排不能逐位元各接一個同步器？

<details><summary>看答案</summary>

各位元到達的時間可能差一個時脈，接收端會看到不存在的中間組合值。要用握手或格雷碼等方法。
</details>

**Q5.** 兩個 `always` 都對 `q` 賦值，會發生什麼事？

<details><summary>看答案</summary>

**多重驅動**：模擬可能出現 `x`，合成工具會報錯或警告。一個訊號只能有一個驅動者。
</details>

2. 找出下列程式的所有問題並修正：

```verilog
always @(posedge clk) begin
  if (a) b = c;
  d <= b;
end
```

3. 把 `mac_pipe` 改成**三級管線**（乘法一級、加法一級、輸出再一級），用 testbench 驗證延遲為 3 個時脈。
4. 實作 `sync2` 並寫 testbench：在 `async_in` 不對齊時脈邊緣的時間點拉高，觀察 `sync_out` 延遲 2 個時脈。
5. 寫一個含有 3 種「意外硬體」的檔案（latch、多重驅動、位寬不一致），用 lint 全部抓出來，再逐一修正。

<details><summary>練習 2 提示</summary>

問題在於**時序區塊中混用阻塞 `=` 與非阻塞 `<=`**：`b = c` 是阻塞賦值，`d <= b` 之後讀到的是「剛剛被更新的 `b`」，行為與「正反器同時更新」的硬體概念不一致，而且 `b` 也沒有重置。修正方向：時序區塊一律用 `<=`，並加上重置：`if (a) b <= c;`。要注意改成 `<=` 之後，`d` 取到的是 `b` 的**舊值**（慢一拍），如果你要的是「用新的 `c`」，應直接寫 `d <= c`。這取決於你想要的行為，所以先畫出時序圖再決定。
</details>
