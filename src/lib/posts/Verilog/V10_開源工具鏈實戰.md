# 第 10 章　開源工具鏈實戰

本章介紹如何用開源工具完成「寫程式 → 模擬 → 看波形 → 檢查 → 合成」的完整流程。

## 10.1 工具分工

| 步驟 | 工具 | 指令 |
|------|------|------|
| 模擬 | Icarus Verilog | `iverilog`、`vvp` |
| 看波形 | GTKWave | `gtkwave wave.vcd` |
| 靜態檢查 (lint) | Verilator | `verilator --lint-only` |
| 合成/分析 | Yosys | `yosys -p "..."` |
| 風格檢查/格式化 | Verible | `verible-verilog-lint`、`verible-verilog-format` |
| Python 測試 | cocotb | 搭配 iverilog / Verilator |

## 10.2 Icarus Verilog

```bash
# 編譯
iverilog -g2005 -Wall -o sim.vvp rtl/counter.v tb/tb_counter.v

# 執行
vvp sim.vvp

# 多個檔案、搜尋路徑、巨集
iverilog -g2005 -Wall -I rtl -DDEBUG -o sim.vvp rtl/*.v tb/tb_top.v
```

常用選項：

| 選項 | 意義 |
|------|------|
| `-g2005` | 使用 Verilog-2005 語法 |
| `-g2001` | 使用 Verilog-2001 語法 |
| `-Wall` | 開啟所有警告 |
| `-o 檔名` | 輸出檔名 |
| `-I 目錄` | `` `include `` 搜尋路徑 |
| `-D 名稱` | 定義巨集 |
| `-s 模組` | 指定頂層模組 |

> 若編譯時遇到 `$clog2` 等函式報錯，確認有加 `-g2005`（或更新 Icarus 版本）。

## 10.3 GTKWave 使用要點

1. `gtkwave wave.vcd` 開啟
2. 左側 **SST** 面板選取模組 → 下方選訊號 → **Append** 加入波形
3. 常用操作：
   - **Zoom Fit**：全部範圍顯示
   - 訊號按右鍵 → **Data Format** → Hex / Decimal / Binary
   - 訊號按右鍵 → **Analog** 可把數值顯示為類比波形
4. **File → Write Save File** 可儲存訊號配置（`.gtkw`），下次直接 `gtkwave wave.vcd view.gtkw`

## 10.4 Verilator：語法與風格檢查

```bash
verilator --lint-only -Wall rtl/counter.v
```

它會指出：

- 位元寬度不一致（`WIDTH`）
- 推導出 latch（`LATCH`）
- 未使用或未驅動的訊號（`UNUSED`、`UNDRIVEN`）
- 組合邏輯迴圈（`UNOPTFLAT`）
- 阻塞/非阻塞賦值誤用（`BLKSEQ`）

```bash
# 若要在警告上暫時忽略特定項目
verilator --lint-only -Wall -Wno-UNUSED rtl/counter.v
```

### 用 Verilator 做模擬（有 `--timing` 支援的版本）

```bash
verilator --binary --timing -Wall --trace tb/tb_counter.v rtl/counter.v
./obj_dir/Vtb_counter
```

Verilator 把設計編譯成 C++，大型設計模擬速度通常明顯快於事件驅動模擬器。

## 10.5 Yosys：合成與分析

### 基本合成與統計

```bash
yosys -p "read_verilog rtl/counter.v; synth -top counter; stat"
```

輸出會顯示使用多少 LUT/閘與正反器。若看到 `$dlatch` 之類的單元，通常表示出現了意外的 latch。

### 輸出網表

```bash
yosys -p "read_verilog rtl/counter.v; synth -top counter; write_verilog -noattr counter_syn.v"
```

### 畫出電路圖（需安裝 Graphviz）

```bash
yosys -p "read_verilog rtl/counter.v; proc; opt; show -format svg -prefix counter"
```

### 針對 FPGA 的合成範例（iCE40）

```bash
yosys -p "read_verilog rtl/top.v; synth_ice40 -top top -json top.json"
```

接著可搭配 `nextpnr-ice40` 做佈局佈線、`icepack` 產生位元流。同一套開源流程也有針對 ECP5 等 FPGA 的版本。這部分的細節依開發板與工具版本不同，請參考各專案的官方文件。

## 10.6 Makefile 範本

> 注意：Makefile 的命令列前面必須是 **Tab** 字元，不能是空白。

```make
TOP  = tb_counter
RTL  = rtl/counter.v
TB   = tb/tb_counter.v

sim: $(RTL) $(TB)
	iverilog -g2005 -Wall -o $(TOP).vvp $(RTL) $(TB)
	vvp $(TOP).vvp

wave: sim
	gtkwave wave.vcd &

lint:
	verilator --lint-only -Wall $(RTL)

synth:
	yosys -p "read_verilog $(RTL); synth -top counter; stat"

clean:
	rm -f *.vvp *.vcd

.PHONY: sim wave lint synth clean
```

使用：`make sim`、`make lint`、`make synth`。

## 10.7 Verible：風格與格式

```bash
verible-verilog-lint rtl/counter.v
verible-verilog-format --inplace rtl/counter.v
```

團隊協作時，用 lint + format 統一風格能減少很多無謂的 code review 討論。

## 10.8 cocotb：用 Python 寫 Testbench

cocotb 讓你用 Python 與 Icarus / Verilator 等模擬器協同模擬，適合複雜的測試邏輯與資料處理（如圖片、檔案、演算法比對）。

```python
# test_counter.py（語法依 cocotb 版本略有差異，請以官方文件為準）
import cocotb
from cocotb.clock import Clock
from cocotb.triggers import RisingEdge

@cocotb.test()
async def counter_counts(dut):
    cocotb.start_soon(Clock(dut.clk, 10, "ns").start())
    dut.rst_n.value = 0
    dut.en.value = 0
    for _ in range(3):
        await RisingEdge(dut.clk)
    dut.rst_n.value = 1
    dut.en.value = 1
    for _ in range(10):
        await RisingEdge(dut.clk)
    assert int(dut.cnt.value) == 10
```

搭配 Makefile 或 `pytest` 風格的 runner 執行，細節見 cocotb 官方文件。

## 10.9 自動化與持續整合

把上述指令寫成腳本後，可放到 GitHub Actions 等 CI 中，每次提交自動跑：

1. `verilator --lint-only -Wall`
2. 所有 testbench 的模擬（以 `$finish` 後的 PASS/FAIL 判斷）
3. （選用）Yosys 合成並檢查沒有 latch

簡易的結果判斷方式：testbench 失敗時以 `$fatal`（若版本支援）或印出特定關鍵字，再用 `grep` 判斷。

```bash
vvp sim.vvp | tee sim.log
grep -q "PASSED" sim.log
```

## 10.10 與 SystemVerilog 的關係

開源工具除了 Verilog 之外，也各自支援不同範圍的 SystemVerilog 語法（例如 `logic`、`always_ff`、`always_comb` 等可合成的設計語法），支援度依工具與版本而異。因此：

- 本講義學到的 Verilog 知識可以直接遷移
- 之後想學 SystemVerilog，可先從「可合成的設計語法」開始，這部分在開源工具中最容易取得支援
- 進階的驗證功能（class、約束隨機化、完整的 SVA 與覆蓋率、UVM）在開源工具中的支援較有限；若需要這些，可考慮 cocotb 或其他開源驗證框架作為替代方案

## 練習

1. 為你的專案建立目錄結構與 Makefile，讓 `make sim`、`make lint`、`make synth` 都可用。
2. 故意寫出 `WIDTH` 與 `LATCH` 的錯誤，觀察 Verilator 的警告格式。
3. 用 Yosys 合成第 8 章的 `sync_fifo`，記錄 `stat` 顯示的單元數量；改變 `DEPTH` 後比較差異。
4. 用 cocotb 重寫第 7 章 `tb_counter` 的部分測試（需先安裝 cocotb）。
