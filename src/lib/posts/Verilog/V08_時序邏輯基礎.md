## 8.1 複習：組合 vs 時序

| | 組合邏輯（第 6 章） | 時序邏輯（本章） |
|---|-------------------|----------------|
| 輸出取決於 | 現在的輸入 | 現在的輸入 **+ 過去存的值** |
| 敏感列表 | `@(*)` | `@(posedge clk)` |
| 賦值符號 | `=` | `<=` |
| 對應硬體 | 邏輯閘 | **正反器** |

## 8.2 第一個正反器

```verilog
module dff (
  input  wire clk,
  input  wire d,
  output reg  q
);
  always @(posedge clk) begin
    q <= d;
  end
endmodule
```

### 逐行解說

| 程式 | 意思 |
|------|------|
| `output reg q` | `q` 在 `always` 裡被賦值，所以是 `reg` |
| `always @(posedge clk)` | **每當 `clk` 發生上升緣，就執行一次**下面的區塊 |
| `q <= d;` | 把 `d` 的值存進 `q`（非阻塞賦值） |

💡 對照第 1 章：這就是「相機快門」。只有時脈上升緣那一瞬間，`q` 才會拍下 `d`；其他時間 `q` 保持不變。

### 🧪 實驗：看 q 什麼時候變

檔名 `tb_dff.v`：

```verilog
`timescale 1ns/1ps
module tb_dff;
  reg  clk = 1'b0;
  reg  d;
  wire q;

  dff dut (.clk(clk), .d(d), .q(q));

  always #5 clk = ~clk;          // 每 5ns 翻轉一次 → 週期 10ns

  always @(posedge clk) begin
    $display("t=%0d  at edge: d=%b  q(before)=%b", $time, d, q);
    #1 $display("t=%0d  after   :        q=%b", $time, q);
  end

  initial begin
    d = 1'b0;
    @(negedge clk) d = 1'b1;     // t=10
    @(negedge clk) d = 1'b0;     // t=20
    @(negedge clk) d = 1'b1;     // t=30
    @(negedge clk) d = 1'b1;     // t=40
    @(negedge clk) d = 1'b0;     // t=50
    repeat (2) @(negedge clk);   // t=60, 70
    #1 $finish;
  end
endmodule
```

新語法說明：

- `always #5 clk = ~clk;`：每隔 5 ns 把 `clk` 反相 → 產生時脈。`~clk` 是反相。
- `@(negedge clk)`：等到下一個下降緣。
- `reg clk = 1'b0;`：宣告時順便給初始值。

### 預期輸出

```
t=5  at edge: d=0  q(before)=x
t=6  after   :        q=0
t=15  at edge: d=1  q(before)=0
t=16  after   :        q=1
t=25  at edge: d=0  q(before)=1
t=26  after   :        q=0
t=35  at edge: d=1  q(before)=0
t=36  after   :        q=1
t=45  at edge: d=1  q(before)=1
t=46  after   :        q=1
t=55  at edge: d=0  q(before)=1
t=56  after   :        q=0
t=65  at edge: d=0  q(before)=0
t=66  after   :        q=0
```

### 怎麼讀這個結果？

- 時脈上升緣在 t=5、15、25…
- **第一行**：t=5 的瞬間，`q` 還是 `x`（還沒存過任何東西），`d=0`
- **第二行**：t=6，`q` 已經變成 0 → 它在 t=5 的上升緣「拍下」了 `d=0`
- **t=15**：邊緣瞬間看到的 `q(before)=0` 是**舊值**，`q` 在這個邊緣之後才變成 1

重點：**每個上升緣，`q` 取到的是「邊緣當下 `d` 的值」，而且 `q` 是在邊緣「之後」才更新。**

## 8.3 阻塞 `=` vs 非阻塞 `<=`（最重要的一節）

### 先背規則

> **組合邏輯（`always @(*)`）：用 `=`**
> **時序邏輯（`always @(posedge clk)`）：用 `<=`**

### 為什麼？用實驗看

要「交換」兩個暫存器的值：

```verilog
module swap_demo;
  reg clk = 1'b0;
  reg [3:0] a1, b1;     // 用 <=
  reg [3:0] a2, b2;     // 用 =

  always #5 clk = ~clk;

  initial begin
    a1 = 4'd1; b1 = 4'd2;
    a2 = 4'd1; b2 = 4'd2;
  end

  // 非阻塞：兩行「同時」發生
  always @(posedge clk) begin
    a1 <= b1;
    b1 <= a1;
  end

  // 阻塞：兩行「一行接一行」
  always @(posedge clk) begin
    a2 = b2;
    b2 = a2;
  end

  always @(negedge clk)
    $display("t=%0d  nonblocking: a=%0d b=%0d   blocking: a=%0d b=%0d",
             $time, a1, b1, a2, b2);

  initial #36 $finish;
endmodule
```

### 預期輸出

```
t=10  nonblocking: a=2 b=1   blocking: a=2 b=2
t=20  nonblocking: a=1 b=2   blocking: a=2 b=2
t=30  nonblocking: a=2 b=1   blocking: a=2 b=2
```

### 為什麼？

**非阻塞 `<=`**：所有右邊先用「**邊緣當下的舊值**」算好，**邊緣結束時一起更新**。

```
邊緣當下：a=1, b=2
  a <= b  → a 要變成「舊的 b」= 2
  b <= a  → b 要變成「舊的 a」= 1
一起更新 → a=2, b=1   ✅ 真正交換
```

**阻塞 `=`**：一行做完才做下一行。

```
a = b;  → a 立刻變成 2
b = a;  → 這時 a 已經是 2 了 → b 也是 2
結果 a=2, b=2           ❌ 沒有交換
```

💡 比喻：非阻塞像「大家同時喊**交換**」；阻塞像「先把 A 蓋成 B 的樣子，才輪到 B 看 A」。

### 為什麼時序邏輯要用 `<=`？

真實的正反器們在**同一個時脈邊緣同時**取樣各自的輸入。`<=` 正好描述這個行為：**全部看「舊值」，一起換成新值**。用 `=` 的話，結果會取決於程式寫的先後順序，模擬與真實硬體可能不一致，這叫**競爭 (race condition)**。

### 常見錯誤

```verilog
// ❌ 時序邏輯用 =
always @(posedge clk) q = d;

// ❌ 組合邏輯用 <=
always @(*) y <= a & b;
```

## 8.4 重置 (Reset)

電路剛通電時，`reg` 的值是 `x`（未知）。需要一個「**重置訊號**」把所有暫存器設成已知的初始值。

### 命名習慣：低態有效 `rst_n`

`_n` 結尾代表「**低電位時有效**」：`rst_n = 0` → 重置中；`rst_n = 1` → 正常運作。

### 同步重置

重置只在**時脈上升緣**才生效：

```verilog
always @(posedge clk) begin
  if (!rst_n)
    q <= 8'd0;
  else
    q <= d;
end
```

### 非同步重置

**不用等時脈**，`rst_n` 一變 0 就立刻重置：

```verilog
always @(posedge clk or negedge rst_n) begin
  if (!rst_n)
    q <= 8'd0;
  else
    q <= d;
end
```

重點：敏感列表多了 `or negedge rst_n`（`rst_n` 的下降緣也會觸發）。

### 對照表

| | 同步重置 | 非同步重置 |
|---|---------|-----------|
| 敏感列表 | `@(posedge clk)` | `@(posedge clk or negedge rst_n)` |
| 何時生效 | 下一個時脈邊緣 | 立刻 |
| 優點 | 時序分析簡單 | 沒有時脈也能重置 |
| 注意 | 需要有時脈在跑 | 「放開」重置時要小心（第 13 章） |

本講義後面**統一用非同步重置、低態有效**。

⚠️ 一定要有 `if (!rst_n)`：敏感列表寫了 `negedge rst_n`，區塊內就必須判斷 `rst_n`，否則會有問題。

## 8.5 致能 (Enable)

只有 `en = 1` 時才更新，否則**保持原值**：

```verilog
always @(posedge clk or negedge rst_n) begin
  if (!rst_n)
    q <= 8'd0;
  else if (en)
    q <= d;
  // en = 0 時什麼都沒寫 → q 保持原值
end
```

### ⚠️ 咦？這不是 latch 嗎？

第 6 章說「沒寫的情況會產生 latch」，這裡也沒寫 `else`，為什麼沒事？

> **在 `always @(posedge clk)` 裡，沒寫就是「保持」，這正是正反器的本性 —— 完全正常。**
> 只有在 **`always @(*)`（組合邏輯）** 裡沒寫，才會產生不想要的 latch。

| 位置 | 沒寫 else 的結果 |
|------|-----------------|
| `always @(*)` | ❌ latch（意外） |
| `always @(posedge clk ...)` | ✅ 保持原值（正常） |

## 8.6 計數器

### 規格

4 位元計數器：重置後從 0 開始；`en = 1` 時每個時脈加 1；數到 15 再加 1 會回到 0。

### 設計

```verilog
module counter4 (
  input  wire       clk,
  input  wire       rst_n,
  input  wire       en,
  output reg  [3:0] cnt
);
  always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
      cnt <= 4'd0;
    else if (en)
      cnt <= cnt + 4'd1;
  end
endmodule
```

📌 `cnt + 4'd1` 的結果放回 4 位元的 `cnt`，所以 15 + 1 = 16 會截成 `0000`，自然回繞（第 5 章的溢位）。

### Testbench

```verilog
`timescale 1ns/1ps
module tb_counter4;
  reg        clk = 1'b0;
  reg        rst_n, en;
  wire [3:0] cnt;

  counter4 dut (.clk(clk), .rst_n(rst_n), .en(en), .cnt(cnt));

  always #5 clk = ~clk;

  always @(negedge clk)
    $display("t=%0d cnt=%0d", $time, cnt);

  initial begin
    $dumpfile("wave.vcd");
    $dumpvars(0, tb_counter4);

    rst_n = 1'b0; en = 1'b0;
    #22 rst_n = 1'b1;                  // 重置放開
    @(negedge clk) en = 1'b1;          // t=30 開始計數
    repeat (5) @(negedge clk);         // 到 t=80
    en = 1'b0;                         // 暫停
    repeat (3) @(negedge clk);         // 到 t=110
    en = 1'b1;                         // 繼續
    repeat (3) @(negedge clk);         // 到 t=140
    #3 rst_n = 1'b0;                   // t=143 中途重置（非同步）
    @(negedge clk);                    // t=150
    rst_n = 1'b1;
    repeat (3) @(negedge clk);         // 到 t=180
    #1 $finish;
  end
endmodule
```

### 預期輸出

```
t=10 cnt=0
t=20 cnt=0
t=30 cnt=0
t=40 cnt=1
t=50 cnt=2
t=60 cnt=3
t=70 cnt=4
t=80 cnt=5
t=90 cnt=5
t=100 cnt=5
t=110 cnt=5
t=120 cnt=6
t=130 cnt=7
t=140 cnt=8
t=150 cnt=0
t=160 cnt=1
t=170 cnt=2
t=180 cnt=3
```

### 逐段對照

| 時間 | 發生什麼事 |
|------|-----------|
| 0~22 | `rst_n=0`，`cnt` 被重置為 0 |
| 30 | 把 `en` 設成 1 |
| 35 | 第一個上升緣，`en=1` → `cnt=1`（t=40 印出 1） |
| 80 | `en=0`，之後上升緣 `cnt` 保持 5（t=90~110 都是 5） |
| 110 | `en=1`，t=115 的上升緣繼續數 → 6 |
| 143 | `rst_n` 變 0，**非同步重置：不用等時脈，`cnt` 立刻變 0**（t=150 印出 0） |
| 150 | 放開重置，t=155 起繼續從 0 往上數 |

### 看波形

```bash
iverilog -g2005 -Wall -o sim.vvp counter4.v tb_counter4.v
vvp sim.vvp
gtkwave wave.vcd
```

在 GTKWave 加入 `clk`、`rst_n`、`en`、`cnt`，並對 `cnt` 按右鍵 → **Data Format → Decimal**，可以清楚看到 `cnt` 每次上升緣加 1，`rst_n` 拉低時 `cnt` 直接歸零。

## 8.7 為什麼 testbench 要在「下降緣」改輸入？

看這個比較：

```verilog
// 在上升緣改輸入 → 危險
always @(posedge clk) en = 1;
```

上升緣時，DUT 也同時在取樣 `en`。如果 testbench 同一瞬間改 `en`，DUT 看到的是舊值還是新值？**不一定**（競爭）。

✅ 習慣做法：**在時脈下降緣改輸入**（離上升緣有半個週期的間隔）。這樣 DUT 在上升緣取樣時，輸入已經穩定了，行為確定。

```
          上升緣取樣↓           上升緣取樣↓
clk  ──┐  ┌──────┐  ┌──────┐  ┌──
       └──┘      └──┘      └──┘
          ↑                ↑
    在下降緣改輸入（離取樣點最遠、最安全）
```

## 8.8 常見錯誤

| 錯誤 | 症狀 | 解法 |
|------|------|------|
| 時序用 `=` | 模擬結果和預期有細微差異、競爭 | 時序用 `<=` |
| 忘了重置 | `cnt` 一直是 `x`，後面全是 `x` | 加上重置與初始值 |
| 重置極性搞反 | 一開始就一直處於重置 | 低態有效用 `if (!rst_n)` |
| 敏感列表寫了 `negedge rst_n` 卻沒有 `if (!rst_n)` | 行為錯誤、工具警告 | 一定要判斷 |
| 同一個 `reg` 在兩個 `always` 賦值 | 多重驅動，出現 `x` | 一個 `reg` 只在一個 `always` 賦值 |
| 以為時序裡沒寫 else 會 latch | 多慮了 | 時序沒寫＝保持，正常 |
| testbench 在上升緣改輸入 | 結果不穩定 | 在下降緣改 |

## 本章小結

- 時序邏輯：`always @(posedge clk or negedge rst_n)` + `<=`
- `<=`：全部看舊值、一起更新；`=`：一行一行依序更新
- **組合用 `=`，時序用 `<=`**
- 非同步重置：不等時脈，`rst_n` 一拉低就歸零；要用 `if (!rst_n)` 判斷
- 時序裡沒寫的情況＝保持，不是 latch
- testbench 在下降緣改輸入

## 小測驗

**Q1.** 如果 `a = 1, b = 2`，在 `posedge clk` 執行 `a <= b; b <= a;`，之後 `a`、`b` 各是多少？

<details><summary>看答案</summary>

`a = 2`、`b = 1`（真正交換）。
</details>

**Q2.** 同樣情況改成 `a = b; b = a;`，結果呢？

<details><summary>看答案</summary>

`a = 2`、`b = 2`（`a` 先被改成 2，`b` 再讀到新的 `a`）。
</details>

**Q3.** 為什麼敏感列表要寫 `negedge rst_n`？它跟同步重置有什麼不同？

<details><summary>看答案</summary>

寫了 `negedge rst_n`，`rst_n` 一拉低就**立刻**觸發重置（非同步），不用等時脈上升緣；同步重置要等下一個上升緣才會生效。
</details>

**Q4.** 下面這段會產生 latch 嗎？

```verilog
always @(posedge clk) begin
  if (en) q <= d;
end
```

<details><summary>看答案</summary>

**不會**。這是時序邏輯，沒寫 else 就是「保持原值」，合成出來是「帶致能的正反器」，完全正常。
</details>

**Q5.** 4 位元計數器數到 15，再加 1 會變多少？

<details><summary>看答案</summary>

16 放不下 4 位元，截掉高位 → **0**。
</details>
