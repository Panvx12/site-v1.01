## 10.1 什麼是狀態機？

💡 生活例子：**電梯**、**自動門**、**紅綠燈**。它們都有幾個「狀態」，依據輸入或時間，從一個狀態跳到另一個。

> **有限狀態機 (Finite State Machine, FSM)**：系統有有限個「狀態」，每個時脈根據「**目前狀態 + 輸入**」決定「下一個狀態」。

### FSM 的三個部分

```
        輸入 ──►┌──────────────┐
                │ 下一狀態邏輯  │ (組合邏輯)
  state ───────►│              │──► next
                └──────────────┘
                        │ next
                        ▼
                ┌──────────────┐
        clk ───►│  狀態暫存器   │ (時序邏輯)
                └──────┬───────┘
                       │ state
                       ▼
                ┌──────────────┐
                │   輸出邏輯    │ (組合邏輯)──► 輸出
                └──────────────┘
```

1. **狀態暫存器**：記住現在是哪個狀態（正反器）
2. **下一狀態邏輯**：算出下一個狀態是什麼（組合）
3. **輸出邏輯**：依狀態（和輸入）決定輸出（組合）

## 10.2 Moore 與 Mealy

| | Moore | Mealy |
|---|-------|-------|
| 輸出取決於 | **只有現在的狀態** | 現在的狀態 **和輸入** |
| 狀態圖上輸出標在 | 狀態裡面 | 轉移箭頭上 |
| 特點 | 輸出穩定、好理解 | 狀態較少、反應快一個時脈 |

初學者**先專心學 Moore**。

## 10.3 狀態圖

用圓圈表示狀態，箭頭表示轉移，箭頭上寫條件。

### 範例：序列偵測器 —— 偵測連續出現 `1 0 1`

規格：輸入一串位元 `din`（每個時脈一個位元）。每當**最近三個位元是 `101`** 就輸出 `found = 1`。允許重疊（`10101` 會偵測到兩次）。

狀態的意義（「我目前已經看到了什麼」）：

| 狀態 | 意義 |
|------|------|
| `S0` | 還沒有任何有用的開頭 |
| `S1` | 剛看到 `1` |
| `S10` | 剛看到 `10` |
| `S101` | 剛看到 `101`（找到！輸出 1） |

狀態圖（箭頭上是 `din` 的值）：

```
        din=0               din=1
      ┌──────┐          ┌──────┐
      ▼      │          ▼      │
    ┌────┐ din=1  ┌────┐ din=0 ┌─────┐ din=1 ┌──────┐
    │ S0 │──────► │ S1 │──────►│ S10 │──────►│ S101 │
    └────┘        └────┘       └─────┘       └──────┘
      ▲   ▲                       │ din=0       │   │
      │   └───────────────────────┘             │   │
      │                                         │   │ din=1 → 回 S1
      │                          din=0 → 回 S10 ┘   └──────► S1
```

用**轉移表**更清楚（寫程式就照著表抄）：

| 現在狀態 | din=0 → 下一狀態 | din=1 → 下一狀態 | 輸出 found |
|---------|:---------------:|:---------------:|:---------:|
| S0 | S0 | S1 | 0 |
| S1 | S10 | S1 | 0 |
| S10 | S0 | S101 | 0 |
| S101 | S10 | S1 | **1** |

幾個重點：

- `S1` 看到 `1`：還是「剛看到 1」，留在 `S1`（例如 `1 1 0 1`，最後的 `101` 仍可成立）
- `S101` 看到 `0`：`101` 的最後 `1` 加上這個 `0` 形成 `10` → 去 `S10`（重疊）
- `S101` 看到 `1`：最後的 `1` 可以當新的開頭 → 去 `S1`

## 10.4 三段式寫法

直接照 FSM 的三個部分，各寫一個 `always`：

```verilog
module seq_detect_101 (
  input  wire clk,
  input  wire rst_n,
  input  wire din,
  output reg  found
);
  // ---- 狀態編碼 ----
  localparam [1:0] S0   = 2'd0,
                   S1   = 2'd1,
                   S10  = 2'd2,
                   S101 = 2'd3;

  reg [1:0] state, next;

  // ---- 第 1 段：狀態暫存器（時序，用 <=）----
  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) state <= S0;
    else        state <= next;
  end

  // ---- 第 2 段：下一狀態邏輯（組合，用 =）----
  always @(*) begin
    next = state;                        // 預設：維持不變
    case (state)
      S0:      next = din ? S1   : S0;
      S1:      next = din ? S1   : S10;
      S10:     next = din ? S101 : S0;
      S101:    next = din ? S1   : S10;
      default: next = S0;
    endcase
  end

  // ---- 第 3 段：輸出邏輯（Moore：只看 state）----
  always @(*) begin
    found = (state == S101);
  end
endmodule
```

### 逐段解說

**狀態編碼 `localparam`**：給狀態取名字，內部用數字表示。`[1:0]` 表示 2 位元，可編 4 個狀態。名字比數字好讀得多。

**第 1 段**：就是一個普通的暫存器。每個時脈 `state <= next`。重置時回到起始狀態 `S0`。

**第 2 段**：純組合邏輯，用 `case (state)` 對照轉移表。

- 開頭 `next = state;` 是**預設值**，避免 latch（第 6 章）
- `din ? S1 : S0` 是「`din` 為 1 選 `S1`，否則 `S0`」
- `default` 讓非法狀態回到 `S0`（安全網）

**第 3 段**：Moore 輸出，只看 `state`。

💡 **三段式的好處**：每一段只做一件事，出錯時容易找；改狀態圖時只要改第 2 段。

## 10.5 驗證

輸入位元串 `1 0 1 0 1 1 0 1 0 0`。**先手算預期**：

| 輸入位元 | 1 | 0 | 1 | 0 | 1 | 1 | 0 | 1 | 0 | 0 |
|---------|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| 讀完後的狀態 | S1 | S10 | **S101** | S10 | **S101** | S1 | S10 | **S101** | S10 | S0 |

找到三次（第 3、5、8 個位元之後）；其中第 3 和第 5 個是**重疊**的 `10101`。

```verilog
`timescale 1ns/1ps
module tb_seq;
  reg  clk = 1'b0;
  reg  rst_n, din;
  wire found;

  seq_detect_101 dut (.clk(clk), .rst_n(rst_n), .din(din), .found(found));

  always #5 clk = ~clk;

  reg [9:0] bits = 10'b1010110100;       // 從左到右依序送入
  integer i;

  always @(negedge clk)
    if (rst_n)
      $display("t=%0d state=%0d found=%b", $time, dut.state, found);

  initial begin
    rst_n = 1'b0; din = 1'b0;
    #22 rst_n = 1'b1;
    for (i = 9; i >= 0; i = i - 1) begin
      @(negedge clk);
      din = bits[i];
    end
    repeat (2) @(negedge clk);
    #1 $finish;
  end
endmodule
```

新語法：`dut.state` 是**階層參考**，直接看 DUT 內部的 `state`（只能在 testbench 用）。

### 預期輸出

```
t=30 state=0 found=0
t=40 state=1 found=0
t=50 state=2 found=0
t=60 state=3 found=1
t=70 state=2 found=0
t=80 state=3 found=1
t=90 state=1 found=0
t=100 state=2 found=0
t=110 state=3 found=1
t=120 state=2 found=0
t=130 state=0 found=0
t=140 state=0 found=0
```

狀態編號 `0=S0, 1=S1, 2=S10, 3=S101`，三次 `found=1` 出現在 t=60、80、110，跟手算完全一致 ✅。

⚠️ 注意是 Moore 的特性：輸入的第三個位元（`1`）在 t=55 被讀進去，`found` 要等到下一次看輸出（t=60）才是 1，輸出比輸入「慢一拍」。

## 10.6 Mealy 版本（了解即可）

Mealy 的輸出也依賴輸入：

```verilog
module seq_detect_101_mealy (
  input  wire clk, rst_n, din,
  output wire found
);
  localparam [1:0] S0 = 2'd0, S1 = 2'd1, S10 = 2'd2;
  reg [1:0] state, next;

  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) state <= S0;
    else        state <= next;
  end

  always @(*) begin
    next = state;
    case (state)
      S0:      next = din ? S1 : S0;
      S1:      next = din ? S1 : S10;
      S10:     next = din ? S1 : S0;    // 偵測到 101 後，最後的 1 當新的開頭
      default: next = S0;
    endcase
  end

  assign found = (state == S10) && din;   // 輸出含輸入
endmodule
```

- 只需要 **3 個狀態**（Moore 要 4 個）
- 在「讀到第三個位元的同一個時脈週期」就能看到 `found=1`，比 Moore **快一拍**
- 代價：輸出會隨輸入變動，若輸入有雜訊，輸出可能出現毛刺

## 10.7 範例：紅綠燈

### 規格

紅燈 3 個時脈 → 綠燈 2 個時脈 → 黃燈 1 個時脈 → 回紅燈，循環。（為了方便模擬用很短的時間；真實的可以改參數。）

### 狀態圖

```
  ┌─────► RED ──(3 clk)──► GREEN ──(2 clk)──► YELLOW ──(1 clk)─┐
  │                                                            │
  └────────────────────────────────────────────────────────────┘
```

### 設計

```verilog
module traffic #(
  parameter RED_T    = 3,
  parameter GREEN_T  = 2,
  parameter YELLOW_T = 1
)(
  input  wire clk,
  input  wire rst_n,
  output reg  red, yellow, green
);
  localparam [1:0] S_RED = 2'd0, S_GREEN = 2'd1, S_YELLOW = 2'd2;

  reg [1:0] state, next;
  reg [7:0] timer;
  reg       done;           // 目前狀態待滿時間了嗎？

  // 判斷這個狀態的時間是否到了
  always @(*) begin
    case (state)
      S_RED:    done = (timer == RED_T    - 1);
      S_GREEN:  done = (timer == GREEN_T  - 1);
      S_YELLOW: done = (timer == YELLOW_T - 1);
      default:  done = 1'b1;
    endcase
  end

  // 第 1 段：狀態暫存器 + 計時器
  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
      state <= S_RED;
      timer <= 8'd0;
    end else begin
      state <= next;
      if (done) timer <= 8'd0;      // 狀態要換了，重新計時
      else      timer <= timer + 8'd1;
    end
  end

  // 第 2 段：下一狀態
  always @(*) begin
    next = state;
    case (state)
      S_RED:    if (done) next = S_GREEN;
      S_GREEN:  if (done) next = S_YELLOW;
      S_YELLOW: if (done) next = S_RED;
      default:  next = S_RED;
    endcase
  end

  // 第 3 段：輸出
  always @(*) begin
    red = 1'b0; yellow = 1'b0; green = 1'b0;    // 預設值，避免 latch
    case (state)
      S_RED:    red    = 1'b1;
      S_GREEN:  green  = 1'b1;
      S_YELLOW: yellow = 1'b1;
      default:  red    = 1'b1;
    endcase
  end
endmodule
```

### Testbench

```verilog
`timescale 1ns/1ps
module tb_traffic;
  reg  clk = 1'b0;
  reg  rst_n;
  wire red, yellow, green;

  traffic dut (.clk(clk), .rst_n(rst_n), .red(red), .yellow(yellow), .green(green));

  always #5 clk = ~clk;

  always @(negedge clk)
    $display("t=%0d light(R,Y,G)=%b%b%b", $time, red, yellow, green);

  initial begin
    rst_n = 1'b0;
    #22 rst_n = 1'b1;

  end
endmodule
```

t=20 light(R,Y,G)=100
t=30 light(R,Y,G)=100
t=40 light(R,Y,G)=100
t=50 light(R,Y,G)=001
t=60 light(R,Y,G)=001

## 10.8 設計 FSM 的完整步驟

1. **用白話寫規格**：有哪些輸入、輸出
2. **列出狀態**：每個狀態代表「我記得什麼」
3. **畫狀態圖／轉移表**
4. 決定 **Moore 或 Mealy**（新手用 Moore）
5. **寫三段式程式**
6. **手算預期結果**，再寫 testbench 比對
7. 檢查**每一條轉移**都有被測到

### 狀態編碼（了解）

| 編碼 | 說明 | 適用 |
|------|------|------|
| 二進位 | 狀態 N 個，用 log₂N 個正反器 | 面積小 |
| 獨熱碼 (one-hot) | 每個狀態一個正反器，N 個，一次只有一個是 1 | FPGA 常用，解碼簡單、速度快 |

初學者先用二進位 `localparam`，足夠了。

## 10.9 常見錯誤

| 錯誤 | 症狀 | 解法 |
|------|------|------|
| 第 2 段沒給 `next = state;` 預設值 | latch | 開頭加預設值 |
| 沒有 `default` | 非法狀態無法恢復 | 加 `default: next = S0;` |
| 狀態位元不夠（4 個狀態卻用 1 位元） | 狀態被截斷 | 位元數 ≥ log₂(狀態數) |
| 把輸出放進第 1 段時序區塊 | 輸出多延遲一拍 | 想要組合輸出就放第 3 段 |
| 重置沒設起始狀態 | 狀態是 `x` | 重置時賦起始狀態 |
| 狀態圖有「死路」（進去出不來） | 卡死 | 檢查每個狀態都有出口 |
| 忘了重疊情況 | 漏偵測 | 想清楚「失敗後該回到哪個狀態」 |

## 本章小結

- FSM = 狀態暫存器 + 下一狀態邏輯 + 輸出邏輯
- 先畫**狀態圖／轉移表**，再寫程式
- **三段式**：時序一段（`<=`）、組合兩段（`=`）
- Moore：輸出只看狀態；Mealy：輸出也看輸入（較快一拍）
- `next = state;` 預設值 + `default` 是好習慣

## 小測驗

**Q1.** 偵測 `101`（允許重疊），在 `S101` 狀態收到 `1`，下一個狀態是什麼？為什麼？

<details><summary>看答案</summary>

**`S1`**。最後的 `1` 可以當作下一個 `101` 的開頭（剛看到 1）。
</details>

**Q2.** Moore 與 Mealy 最大的差別？

<details><summary>看答案</summary>

Moore 的輸出只取決於**狀態**；Mealy 的輸出取決於**狀態與輸入**。
</details>

**Q3.** 三段式裡，哪些段用 `<=`、哪些用 `=`？

<details><summary>看答案</summary>

第 1 段（狀態暫存器，時序）用 `<=`；第 2、3 段（組合）用 `=`。
</details>

**Q4.** 7 個狀態的 FSM，二進位編碼至少需要幾個位元？

<details><summary>看答案</summary>

2³ = 8 ≥ 7，所以需要 **3** 位元。
</details>

## 練習

1. 設計**非重疊**的 `101` 偵測器（偵測到後，要重新開始、不重複使用最後的 `1`）。先畫狀態圖。
2. 設計一個**自動販賣機**：只收 5 元與 10 元，累計達 15 元就出貨（`dispense=1`）並歸零。輸入 `coin5`、`coin10`（不會同時為 1）。提示：狀態用「目前累積金額」：0、5、10；到 10 時投 5 元或投 10 元會達 15 以上，不用多記餘額。
3. 修改 `traffic`，加入輸入 `pedestrian`（行人按鈕）：黃燈結束後若 `pedestrian=1`，紅燈時間延長 2 個時脈。
4. 把 `seq_detect_101` 改寫成**獨熱碼**，並用同一個 testbench 驗證輸出相同。
5. 設計一個偵測 `1 1 0` 的 FSM（Moore，允許重疊），先手算預期，再寫 testbench 驗證。
